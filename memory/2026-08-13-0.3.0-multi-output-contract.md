# 2026-08-13 0.3.0 Multi-Output Contract

## Objective

- Replace the single-body processor API with a clean, general, versioned
  multi-output contract for the V7 media-server integration.

## User-Approved Scope

- Backward compatibility is intentionally not retained.
- Keep processor contracts product-neutral; V7 recipe presets remain owned by
  the future media-server.
- Prepare version `0.3.0`, split coherent commits, and open a draft PR linked to
  issue #17. Do not tag, publish, deploy, or switch V7 consumers yet.

## Implementation Status

- Completed: v1 image recipe/manifest/problem contracts, multipart HTTP API,
  bounded image fan-out, explicit video normalization, hardened release image,
  contract generation/drift checks, tests, and documentation.
- Partial: GitHub PR checks still need to run after the draft PR is opened.
- Not started: processor tag/GHCR publication and V7 media-server integration.

## Major Changes

- Files/modules: `src/app.ts`, `src/contracts.ts`, `src/recipe.ts`,
  `src/image.ts`, `src/video.ts`, `src/multipart.ts`, `src/concurrency.ts`, and
  checked files under `contracts/`.
- API / interface changes: removed `POST /process`; added
  `POST /v1/images/process` and `POST /v1/videos/process`. Image success uses
  canonical manifest-first `multipart/related` with exact digest bindings.
- Config / environment changes: strict reviewed ceilings; malformed or expanded
  safety limits fail startup. Images use one admission slot and videos use the
  full capacity through response EOF/cancel/deadline. Video admission rejects
  non-8-bit 4:2:0 inputs and decoded working sets above 192 MiB. The supported
  Linux deployment profile uses a 2 GiB container, a fixed 768 MiB child
  address-space fence, and only `ultrafast|superfast|veryfast` video presets.
- Styles / assets: none.
- Tests: boundary, deadline, animation, metadata privacy, multipart, contract,
  one-byte-chunk coalescing, response-lifetime admission, video resource,
  Docker hardening, tiny-tmpfs, and no-egress processing coverage.

## Validation

- Commands run: `bun run check`, `docker build`, exact-image multipart verifier,
  hardened runtime inspection, normal 1080p and exact-maximum 100 MiB video,
  1 MiB tmpfs failure/cleanup, and `--network none` image processing.
- Result: 84 tests passed, zero failures. The 100 MiB video completed under the
  2 GiB release profile with a measured local cgroup peak of about 469 MiB, no
  OOM, and healthy follow-up. A 1 MiB tmpfs produced the typed 503 failure,
  removed temporary files, and left the server healthy. The image build and
  listed container smoke checks passed.
- Skipped checks: no tag workflow, registry push, production deployment, or V7
  consumer integration was executed.

## Remaining Work

- Suggested next entry points: merge/release processor v0.3, then implement the
