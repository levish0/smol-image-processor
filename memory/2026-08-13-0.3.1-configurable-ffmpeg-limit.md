# 2026-08-13 0.3.1 Configurable FFmpeg Limit

## Objective

- Replace the universal fixed FFmpeg/ffprobe 768 MiB address-space assumption
  with an operator-owned deployment profile while preserving the reviewed
  default and keeping the Bun service isolated from child resource exhaustion.

## User-Approved Scope

- Keep the v0.3 HTTP, recipe, manifest, and problem-response wire unchanged.
- Add a strict `FFMPEG_ADDRESS_SPACE_LIMIT_BYTES` deployment setting.
- Keep container RAM/swap in the deployment orchestrator rather than coupling
  processor configuration to cgroup discovery.
- Fail startup on malformed, zero, negative, or unsafe-integer values.
- Prepare a patch release because v0.3.0 was already tagged and published.

## Implementation Status

- Completed: strict config wiring, health diagnostics, unit coverage, Docker
  workflow coverage, version/docs/changelog updates.
- Partial: none.
- Not started: tagging or publishing v0.3.1.

## Major Changes

- Files/modules: config/policy/video/app wiring.
- API / interface changes: additive `ffmpeg_address_space_limit_bytes` on
  `/health`; media processing wire is unchanged.
- Config / environment changes: optional
  `FFMPEG_ADDRESS_SPACE_LIMIT_BYTES`, default 768 MiB, positive safe integer.
- Styles / assets: none.
- Tests: default/custom/invalid values, health exposure, selected `prlimit`

## Remaining Work

- Known gaps: review/merge PR #19 before creating the signed tag.
- Risks: address-space, physical container memory, and swap are separate
  operator-owned limits; an excessively large child setting can let the outer
  container limit become the final OOM boundary.
- Suggested next entry points: `src/config.ts`, `src/video.ts`, and the hardened
  smoke in `.github/workflows/docker.yml`.

## Notes For Next Agent

- Do not turn this environment setting into a caller-selected recipe field.
- Do not silently clamp unsafe values; startup must remain fail-closed.
- A child limit failure should stay a typed 503 with cleanup. A whole-container
  OOM is handled by orchestration restart and upstream durable retry.
